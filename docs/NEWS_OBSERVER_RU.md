# Наблюдение новостей MOEX ISS (не торговый источник)

`moex-news-observer.timer` опрашивает официальный ISS каждые 5 минут на 45-й
секунде. Расписание независимо от торговых таймеров. `execution_allowed=false`.
Служба не загружает `bot.env`, не имеет доступа к торговому состоянию и секретам,
не вызывает брокерский API. Ни LONG, ни intraday, ни геориск не читают её результаты.
Существующий RSS остаётся в `geo_sources.json`; его сбой не маскируется.

## Конфигурация `config/news_observer.json`

| Параметр | Значение | Значение для наблюдения |
|---|---|---|
| `mode` | `observation_only` | Единственный разрешённый режим |
| `execution_allowed` | `false` | Включение исполнения запрещено валидатором |
| `lookback_hours` | 48 | Скользящее окно публикаций; максимум 168 часов |
| `max_pages` | 40 | Предел пагинации; достижение без покрытия окна — ошибка |
| `timeout_seconds` | 10 | Максимальное ожидание одного HTTP-запроса |
| `budget_seconds` | 90 | Общий бюджет пагинации ISS; RSS получает свой timeout |

`config/monitoring.json: news_observer_enabled=true` включает контроль свежести
отдельного наблюдателя. Это не разрешает использовать новости для сделок.

## Артефакты и трактовка

Каталог `/var/lib/moex-news-observer` содержит `latest.json` и `news.sqlite3`.
В SQLite таблица `runs` хранит неизменяемые снимки каждого наблюдения; `news` —
первое обнаружение ID. Сохраняются публикации, заголовки, ссылки через MOEX ID,
SHA256 страниц, смещения пагинации и время получения. Обновлённые заголовки видны
в последующих снимках; прошлые решения и снимки не переписываются.

- `iss.window_covered=true`: успешно пройдено окно ISS, **не доказательство**, что
  этот API содержит все новости биржи. Повторы ID, сдвиг/нарушение сортировки,
  страницы с неверной схемой, будущие даты и обрыв пагинации не дают PASS.
- `comparison=MATCH`: все элементы доступного RSS **в текущем окне** найдены
  по ID с теми же заголовками и временем публикации. Это сравнение подмножества
  риск-параметров с общей лентой; лишние новости ISS не считаются ошибкой.
- `UNAVAILABLE`: ISS или RSS недоступен; полнота не проверена.
- `NO_REFERENCE_ITEMS`: в окне нет элементов RSS; это не положительное доказательство.
- `DIFFERENCES`: отсутствующие ID либо несовпадение заголовка/времени, требующее разбора.
  RSS запрашивается после ISS, поэтому новая публикация между запросами также
  может объяснить расхождение; автоматически исправлять или дополнять данные нельзя.

Наивные даты ISS интерпретируются в Europe/Moscow (сопоставлены с RSS +0300),
хранятся в UTC. Первое заполнение БД — `baseline`, не задержка доставки.
`forward_new` и `delays_seconds` относятся только к впервые обнаруженным после
старта наблюдения новостям, опубликованным после старта. Это время от публикации
до обнаружения, включая период опроса, сеть и простои, **не чистая задержка API**.
Старые вновь обнаруженные записи отмечаются как historical backfill.
Отсутствие новых новостей означает `median_seconds=null`, не нулевую задержку.

## Мониторинг

- `api:geo_moex_risk`: исходный RSS, независимо проверяется текущим мониторингом.
- `api:news_iss_observer`: результат последнего полного обхода ISS, только наблюдение.
- `data:news-observer`: отчёт не старше 15 минут; отсутствие отчёта не считается UP.
- `timer:news-observer`: работает ли отдельный таймер.

Kuma показывает RSS и ISS отдельными Push-мониторами. RSS продолжает отправлять
один переход через существующий geo-relay; дублирующий webhook этого RSS-монитора
подавляется. ISS имеет собственное оповещение. Успех ISS не восстанавливает RSS.

## Установка / проверка

После штатного `update.sh` (он устанавливает unit-файлы, но не включает новый таймер):

```bash
sudo systemctl daemon-reload
sudo systemctl start moex-news-observer.service
sudo systemctl enable --now moex-news-observer.timer
sudo journalctl -u moex-news-observer.service -n 15 --no-pager
sudo moex-botctl diagnose --once
```

Новые мониторы добавляются штатным `migrate-kuma-monitors.py`: сначала dry-run,
затем резервная копия и миграция **при остановленной Kuma**, не live-редактирование
SQLite. После запуска Kuma — `kuma-exporter.py --provision`, обновление копии relay
и перезапуск только мониторинговых служб. Торговые службы для этого не запускаются.

Перевод ISS в источник торгового геориска требует отдельного согласования:
состав общей ленты отличается от RSS cat=122.

Официальные методы: https://iss.moex.com/iss/reference/231 и
https://iss.moex.com/iss/reference/229. RSS: https://www.moex.com/a40.
