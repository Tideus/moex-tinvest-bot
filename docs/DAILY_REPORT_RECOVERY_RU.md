# Завершённые дневные отчёты и повторный запуск

LONG sandbox и контроль LONG ИИС публикуют датированный JSON как основной документ,
а TXT — как его представление. Отдельный файловый lock не допускает двух издателей
одного отчёта; запись каждого файла атомарна. Торговые журналы и заявки не изменяются.

После успешной публикации повторный запуск, включая рестарт после обновления,
использует сохранённый отчёт без запроса текущего портфеля. Дата, P&L, оценки,
состояние защиты и время среза остаются историческими. Telegram использует прежний
ключ дедупликации; повторный запуск не означает повторную рассылку.

## Если запуск произошёл днём

- Есть проверенный финальный отчёт за выбранную дату: `PRESERVED`, без чтения брокера.
- Нет финального отчёта: `UNAVAILABLE / outside_close_window_no_final_report`, exit 2.
  Сегодняшний портфель не подставляется в прошлый день; существующие файлы не стираются.
- Есть close, но нет пригодного финального отчёта: требуется восстановление исходных
  доказательств, а не новая оценка счёта.

Техническая попытка сохраняется рядом в `*.attempt.json`: дата отчёта, время попытки,
статус, этап и ограниченный код причины. Она не подменяет итоговый JSON.
Если закрывающая оценка получена, но нет начальной, P&L остаётся «н/д», не нулём;
такой новый отчёт также сохраняет исходный срез и не дополняется будущими наблюдениями.

Окно получения закрывающей оценки здесь прежнее: 23:50–06:50 МСК следующего дня.
Расписание 23:55, стратегии и лимиты этим исправлением не меняются. Это защита
публикации, не новая реализация календаря торгов. Параметр `--report-date` не разрешает
получить историческую оценку путём чтения сегодняшнего счёта.

## Восстановление старого перезаписанного отчёта

1. Сверить SHA256 резервного архива и точные имена файлов нужной даты.
2. Сохранить повреждённую версию отдельно для аудита.
3. Проверить дату/время закрытия и привязку счёта исходного JSON и close.
4. Атомарно восстановить только исходные JSON/TXT этой даты, с прежними правами.
5. Повторный read-only запуск должен вернуть `PRESERVED`, не обращаться к брокеру
   и не менять хеш финального JSON или close. Торговые БД не восстанавливать и
   старые решения не пересчитывать.

## Диагностика T-Invest API

Проверки SANDBOX и PROD остаются независимыми. В diagnose, Kuma и алерте теперь
сохраняются безопасные названия метода и этапа:

- `UsersService/GetAccounts` — PROD;
- `SandboxService/GetSandboxAccounts` — SANDBOX;
- `request` — DNS/TCP/TLS или ожидание HTTP-заголовков; точную сетевую стадию
  нельзя установить только по исключению urllib;
- `response_body` — чтение тела ответа;
- `response_schema` — проверка JSON/формата.

Таймаут и исходный FAIL не подавляются повторными запросами. Токены, URL с секретами,
полные ID и текст исключений в сообщения не попадают. Успех ISS не снимает отказ RSS.
