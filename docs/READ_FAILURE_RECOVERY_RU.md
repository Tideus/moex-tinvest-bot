# Обрывы чтения и сопровождение intraday

`IncompleteRead` означает обрыв тела HTTP-ответа. Тайм-аут чтения означает,
что клиент не дождался ответа. Ни то, ни другое само по себе не доказывает
полную недоступность поставщика: проверка API позже может пройти успешно.

## Повторы

- ALGOPACK повторяет чтение страницы при обрыве ответа, тайм-ауте и временной
  сетевой ошибке. По умолчанию максимум три попытки с прежними параметрами.
- T-Invest повторяет только явно перечисленные методы чтения на двух
  штатных адресах API; максимум три попытки, паузы 0,5 и 1 секунды.
  Тайм-аут каждой попытки берётся из вызывающего адаптера.
- BUY, SELL, стопы, отмены и операции со счетами **не повторяются** транспортом.
  Оборванный ответ на отправку заявки означает неизвестный результат:
  сначала сверка с брокером, а не повторная покупка.
- Ошибки авторизации, валидации и TLS не являются основанием для повторов
  в транспорте T-Invest. Некорректный JSON не подменяется пустым ответом.

## Что сохраняется и отображается

В intraday-плане `analysis_input.read_failure` сохраняет безопасное описание
неудачного чтения: источник, набор данных, тип сбоя. Токен, ID счёта,
фрагмент ответа и параметры URL не включаются.

Если из-за этого не пройдено качество плана, существующая метрика
`quality:intraday` указывает конкретный набор ALGOPACK. Её описание в
мониторинге отличает ошибку последнего цикла от текущего состояния API.
Новый параллельный канал оповещений не создаётся; действующие правила
дедупликации/маршрутизации сохраняются. В журнале T-Invest указываются
контур sandbox/prod, метод чтения, тип ошибки и число попыток.

При отсутствии ALGOPACK новые входы запрещены. Выходы из уже открытых
позиций по стоп-условию, времени удержания и завершению сессии используют
имеющийся брокерский снимок. Если получить сам брокерский снимок не удалось,
бот не выдумывает позиции или цены и сообщает ошибку.

Прошлые решения не переписываются. Стратегии, лимиты и расписания не меняются.
Одноразовый LONG-журнал не сбрасывается этим исправлением; повторный допуск
нельзя получать удалением БД или независимого защитного маркера.
