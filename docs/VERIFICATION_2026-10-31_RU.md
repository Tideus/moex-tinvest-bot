# Проверка 0.7.0rc2 — 31 октября 2026

## Воспроизводимые результаты

Windows Python 3.12.14 и Ubuntu Python 3.12.3: **1439 тестов проходят**.
Для всего Python-пакета `src/moex_bot` (51 модуль) покрыты **7078/7078 строк
и 2496/2496 ветвей**. В `live_execution.py` покрыты 230/230 строк и 100/100 ветвей.
Отдельно покрыты журнал исполнения, live operator, sandbox и PROD HTTP-адаптеры,
планировщик исполнения, миграции, аналитика, отчёты и мониторинг.

```bash
python -m pytest -p no:cacheprovider --cov=moex_bot --cov-branch \
  --cov-report=term-missing --cov-report=json:coverage.json --cov-fail-under=100
python -m ruff check .
python -m mypy src
python -m moex_bot.cli config-check
bash scripts/ubuntu/test-deployment.sh
```

Ruff и strict mypy проходят; 22 конфигурации валидны. Linux smoke-test проверяет
staged install, Bash-синтаксис, сертификаты, права, runner/health, backup и reset
на изолированных данных с подменёнными системными командами. Shell/JS/конфиги
не входят в Python coverage denominator: для них используются контрактные тесты
и smoke-проверки. Сетевые и брокерские побочные эффекты в unit tests подменены.

Артефакты: `artifacts/coverage-final-{windows,linux}.json` и
`artifacts/tests-final-{windows,linux}.xml`. Они не содержат токенов и не включены в Git.
CI требует 100% строк и ветвей всего пакета и отдельно 100% live-execution.
Новые `omit`/`no cover` не добавлялись; два старых исключения ImportError удалены
и заменены тестами. Недостижимый повторный early-return в ExecutionJournal удалён
с отдельного разрешения владельца; исходный запрет повторной подачи сохранён.

## Алерты и миграция

Подробности: [monitoring.md](monitoring.md). Мониторы разделены на торговые,
общесерверные и инфраструктурные. T-Invest sandbox/PROD различимы, причины сбоя
фильтруются по категории и не раскрывают сырой ответ API/секретный URL.

Offline-миграция Kuma проверена на тестовой схеме и dry-run реальной схемы:
не требует обхода авторизации, работает только при остановленном контейнере,
делает приватную backup до транзакции, сохраняет историю и notification bindings.
Независимый аудит выявил и помог закрыть коллизии имён, неполную фильтрацию
категорий и окно создания секретного файла с общедоступными правами.

Перед переключением обнаружено и исправлено разрешение путей systemd-файлов
установщика Kuma: штатный `scripts/ubuntu` теперь использует `deploy/ubuntu`;
поддержаны явный `--units-source` и старый bundle-layout. Все пять входных файлов
проверяются до первой записи, для каждого отсутствующего файла есть регрессия.

## Границы результата

Покрытие не является доказательством прибыльности, безошибочности или исполнения
реального PostOrder. PROD admission, лимиты, защита ручных позиций и отключение
автономной торговли не снимаются. Обновление должно сохранять остановленные
торговые таймеры. Внешний watchdog, SMTP fallback и полноценная аварийная
репетиция восстановления остаются отдельными задачами.
