# LONG: независимый forward-эксперимент 11:05

Статус: только исследование. Это не повторная заявка и не разрешение PROD.
Протокол `long-flow-forward-v1` фиксируется до накопления результатов.

## Что сравниваем

- Текущий фильтр ALGOPACK по одному закрытому интервалу.
- Тот же фильтр, но дисбаланс стакана — среднее 3 последовательных интервалов.
- Тот же фильтр, но дисбаланс стакана — среднее 6 последовательных интервалов.

Порог спреда остаётся 3 базисных пункта (0,03%). Пороги потока сделок
−0,25, потока заявок −0,10 и стакана −0,20 не меняются. В двух альтернативных
ветках усредняется только стакан, не остальные признаки. Это новые гипотезы,
а не уже доказанные прибыльные стратегии.

## Время и условия

Наблюдатель запускается по будням в **11:05:30 МСК**, без догоняющего запуска
после перезагрузки. Время отсечения данных фиксируется до сетевых запросов.
Данные считаются доступными не раньше метки интервала + 5 минут + 15 секунд
либо более позднего `systime`. Будущие и слишком старые значения исключаются.
Решение фиксируется после завершения сбора; после 11:20 наблюдение отклоняется.

Берётся первый штатный утренний план за текущую дату из окна 10:05–10:25 МСК.
Сверяются SHA-256 портфельного входа, конкретный LONG sandbox и версия стратегии.
Фиксируется та же дневная пятёрка momentum; новая дневная свеча не подмешивается.
Утренний геориск должен быть normal; нового геоанализа в исследовательском
наблюдателе нет. Поэтому его вывод не является полноценным торговым допуском.

Повторная оценка разрешена только если журнал остаётся `WAITING`, нет позиций,
обычных и стоп-заявок. Проверка повторяется после сбора. Совершённая или
попытанная утренняя покупка не перевооружается. При нехватке текущих данных
кандидат не выбирается; разрыв окна 3/6 баров отмечается отдельно.

Одна неизменяемая запись на дату. Ручной повтор не заменяет неудачное наблюдение
удачным. Ошибка сбора отражается в журнале systemd и отсутствием наблюдения,
а не вымышленным «сигнала не было». После 40 оценённых сессий новые оценки
останавливаются; после 20 и 40 нужна ручная оценка. Календарный выходной без
утреннего плана не должен засчитываться как проверенная торговая сессия.

## Разделение с торговым ботом

Код устанавливается в `/opt/moex-long-flow-shadow`, состояние —
`/var/lib/moex-long-flow-shadow`. Наблюдатель использует установленную rc10 как
библиотеку, но не обновляет её. Он не пишет в runtime, strategy config, sandbox
или PROD execution journal. Транспорт разрешает только чтение Sandbox API;
PROD-токены удаляются из окружения unit. Нет методов покупки, продажи,
постановки стопа, отмены заявки или восстановления исполнения.

Утренний LONG sandbox продолжает действовать по прежним правилам.
Intraday не меняется. Включение эксперимента **не включает** ИИС.

## Отчётность и ограничения

В 23:57 МСК отдельный отчёт помещается в штатную надёжную очередь Telegram.
Его доставляет существующий отправитель бота; одинаковые отчёты дедуплицируются.
Если сервер был выключен, отчёт строится за последнюю закрытую дату.

В JSON сохраняются утренние признаки и причины, SHA-256 исходного плана,
выбранные TradeStats/OrderStats/OBStats с временными метками, вариант фильтра,
один первый кандидат на вариант и все отказы. Полный account ID не записывается.
Дневной накопительный JSON содержит движение всех оценённых кандидатов,
включая отклонённых: +60 минут, 18:40 и +1/+5 наблюдаемых будних сессий.
Незрелые горизонты и отсутствующие котировки не превращаются в нулевую прибыль.

Референсная цена: открытие первой 10-минутной свечи после решения + 60 секунд.
Издержки: комиссия 5 б.п. и проскальзывание 2,5 б.п. с каждой стороны, половина
наблюдаемого входного спреда и половина **модельного выходного спреда 3 б.п.**.
В отчёте есть обычные и двойные издержки. Это допущение, а не тариф пользователя.
Свечи и издержки дают price markout, **не fill и не P&L счёта**: очередь лимитной
заявки, стоп, гэпы исполнения, портфельные ограничения и дивиденды не моделируются.

Прежде чем переносить результат в торговлю: сверить полноту 20–40 сессий,
сравнить варианты на одних зрелых горизонтах и датах, проверить вклад единичных
выбросов, провести симуляцию исполнения/стопа и независимую проверку.
Технический или исследовательский успех не включает PROD автоматически.

## Установка и управление

При отказе контроля качества уже привязанного утреннего плана эксперимент
сохраняет `DATA_MISSING` с SHA исходного плана. Не ранжирует бумаги, не
подставляет свежие данные вместо утренних, не считает пропуск нулевой доходностью.
Несовпадение SHA/счёта либо стратегии остаётся ошибкой, а не штатным пропуском.
При техническом сбое этап и тип ошибки попадают в журнал и отдельную квитанцию
`failures/YYYY-MM-DD.json`; запись не является торговым решением.
После ошибки сбор не следует перезапускать для восстановления прошлого наблюдения.

Отдельная локальная служба `moex-long-flow-shadow-alert.service` без сети и
брокерских ключей ставит одно техническое сообщение за день в очередь алертов.
Обычное отсутствие кандидатов не вызывает алерт. Для проверки используйте
`journalctl -u moex-long-flow-shadow.service -u moex-long-flow-shadow-alert.service`.
Сбой проверки данных не означает, что брокер или вся биржа недоступны.

Из проверенного checkout (рабочий бот не обновляется):

```bash
sudo bash scripts/ubuntu/install-long-flow-shadow.sh
sudo systemctl enable --now moex-long-flow-shadow.timer moex-long-flow-shadow-report.timer
systemctl list-timers 'moex-long-flow-shadow*'
sudo journalctl -u moex-long-flow-shadow.service -u moex-long-flow-shadow-report.service --since today
```

Установщик останавливает только старые units этого эксперимента, если они есть.
После повторной установки timers нужно явно включить той же командой.
SHA-256 установленного скрипта: `/opt/moex-long-flow-shadow/SOURCE_SHA256`.

Остановить только эксперимент:

```bash
sudo systemctl disable --now moex-long-flow-shadow.timer moex-long-flow-shadow-report.timer
sudo systemctl stop moex-long-flow-shadow.service moex-long-flow-shadow-report.service
```

Это отдельные units, не торговые timers `moex-tinvest-*`. Остановка основного
бота не подразумевает остановку эксперимента; для полного обслуживания сервера
нужно остановить обе группы. Удаление истории не требуется и не автоматизируется.
Для восстановления на новой VM сохранить вместе весь каталог
`/var/lib/moex-long-flow-shadow` и установленный скрипт с `SOURCE_SHA256`;
стандартный backup бота этот отдельный каталог не включает.

Локальная проверка: `python -m pytest tests/test_long_flow_forward.py`.
Проверка типов: `python -m mypy --strict src/moex_bot scripts/research/long_flow_forward.py`.
