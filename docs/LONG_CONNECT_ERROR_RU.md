## Исправление в коде (не изменение стратегии)

- Все чтения MoexAlgoReadOnlyAdapter имеют границы ticker/metadata/candles/
  historical_candles. До трёх попыток только при ConnectError/ConnectTimeout,
  задержки 0,25 и 0,5 с. Параметры запроса и as_of не сдвигаются.
- Это ограничение числа попыток, не общий wall-clock deadline; исходный
  таймаут библиотеки и лимит времени systemd продолжают действовать.
- TLS/сертификаты и HTTP 401/403/429/5xx не повторяются автоматически;
  проверка TLS не отключается. Брокерские записи не оборачиваются в retry.
- HTTPX-ошибка преобразуется в безопасную MarketDataReadError. Сохраняются
  API, разрешённый host/path, операция, тикер, класс ошибки, категория,
  HTTP status и число попыток. Ни query, ни headers/body, ни сырой текст
  исключения не попадают в журнал. Неизвестный endpoint скрывается.
- CLI возвращает ошибку, не создаёт торговый план, пишет plan.error.json
  и ставит health_failure в outbox. Контур указан отдельно от общего MOEX API.
- --failure-outbox включает только технические алерты, не торговые отчёты.
  Обычный shadow/PROD observer использует имеющийся --outbox. У sandbox LONG
  writer остаётся запрет записи в рабочий outbox: read-only verifier читает
  свежие plan.error.json и ставит технический алерт со своей стороны.
  Доставка идёт штатным отправителем в
  TELEGRAM_ALERT_CHAT_ID (при отсутствии — штатный fallback в основной чат).
- PR6 переносит структурированную ошибку в cycle и stderr, ставит code=2
  даже при неожиданном исключении. Изоляция PR6 сохранена: доступа к
  рабочему outbox или Telegram у него не добавлено.

## Как понимать алерт

`LONG · SANDBOX · данные недоступны` означает, что чтение MOEX нарушило
расчёт sandbox-плана, а не что упал sandbox API брокера. Далее указаны host,
операция, тикер, категория dns/tls/connection/http и попытки.
`unknown/withheld` означает отсутствие безопасно установленного адреса,
а не подтверждённый отказ определённого endpoint.

Отсутствие плана не равно отсутствию сигнала. Не повторять брокерские заявки
по такому алерту. Сначала проверить доступность указанного API и журнал.
Сетевое соединение можно проверить без токена; 401 на apim без токена ожидаем.
Если алерт не пришёл, проверить очередь и её доставку отдельно.
