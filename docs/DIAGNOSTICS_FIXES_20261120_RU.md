# Уточнение диагностики 20 ноября 2026

Изменения только в проверках и отчётности. Стратегии, риск-лимиты, допуски,
календарь и расписания торговых контуров не изменяются. PROD не включается.

## LONG: устаревший пакет проверки — не сбой покупки

На vivek установлен новый релиз, а независимый пакет проверки от 8 ноября
привязан к `a87cc811`. Проверка правильно возвращает `REVIEW_INVALID`.
Дефект: причина раньше терялась, оставался только `ValueError`.

Теперь сохраняются `failure_stage`, `failure_reason`, безопасный класс ошибки.
Например: `deployment_revision / release_changed` — нужен новый аудит конкретного
релиза. В Telegram показывается объяснение и явное «НЕ разрешение на торговлю».
Неизвестные исключения не передают текст, URL, данные счёта или секреты.
Повтор одинаковой причины не создаёт новых сообщений: используется прежняя
устойчивая дедупликация. Исторические отчёты не перезаписываются.

Вспомогательные скрипты перенесены в версионируемый релиз из установленной
версии с проверкой SHA256. Их защитные условия сохранены. Установщик обновляет
только два скрипта существующего наблюдателя, проверяя оба перед заменой.
Он не создаёт новый допуск, не обновляет `review.json`, не заменяет доказательства,
не меняет unit-файлы и не запускает торговые службы. Неизвестные локальные правки
скриптов блокируют их автоматическую замену.

## Ночной research shadow

19 ноября решения собраны во всех ожидаемых слотах, но есть реальная неполнота:
23 записи ошибок источников/валидации, один отсутствующий decision quote на вариант
intraday и пропуски последующих котировок на горизонтах 30/60 минут.
Это не 23 независимых сетевых инцидента: одна ошибка получения данных может
порождать несколько записей валидации, а стратегии используют общие котировки.

Report-only wrapper теперь выводит ограниченную безопасную сводку в systemd:
число ошибок по известным источникам/классам, ожидаемые/записанные/пропущенные
решения и отсутствующие котировки по стратегии/горизонту. Неизвестные счётчики
показываются как null, а не ноль. Полный JSON остаётся приватным.
Frozen-протокол, сборщик, registry, модель и прошлые решения не меняются.
`INCOMPLETE`, код 3 и отдельный FAIL мониторинга остаются.

## diagnose и RSS

Общая проверка health раньше называлась «Последний цикл свежий», хотя могла
провалиться только из-за RSS или исследования. Теперь название и подсказка
описывают весь проверяемый набор и требуют читать конкретную строку FAIL.

20 ноября RSS `www.moex.com:443` с vivek не установил TCP-соединение даже при
явном IP 85.118.181.8 и без proxy. DNS совпадает с ноутбуком, маршрут существует,
политика iptables OUTPUT — ACCEPT. Ноутбук получает HTTP 200; ISS с vivek также
получает HTTP 200. Это локализует сбой в сетевом пути/фильтрации к www.moex.com,
но не доказывает, какая сторона его фильтрует. Требуется разбор у хостера/Мосбиржи.
Источник не заменён и не отключён. RSS и ISS остаются независимыми метриками;
успешный ISS не делает геоисточник RSS исправным.

## Проверки

Регрессии: смена релиза без автоматического переподтверждения, нарушение
целостности, отсутствие/изменение доказательств, неверный хеш sandbox receipt,
отсечение старых/чужих/будущих подтверждений, неизвестные ошибки без утечек,
атомарная публикация, дедупликация уведомлений, сохранение отчётных пропусков,
совместимость frozen-report и разделение RSS/ISS.

Приёмка релиза: полный pytest на Windows и изолированном Linux, Ruff,
strict mypy, Linux deployment smoke; после установки — version, prelaunch,
diagnose и штатный запуск неавторизующего наблюдателя. Ожидаемый остаточный
UNHEALTHY из-за RSS/неполноты исследования не является успешной доступностью.

Итог полного прогона: Windows — 3035 passed, 21 платформенный skip;
Linux — 3054 passed и 2 root-only skip, затем оба root-only теста прошли отдельно.
Итого на Linux проверены все 3056 тестов. Ruff, strict mypy (94 файла) и
deployment smoke прошли. Начальный отказ localhost-теста Windows был
`WinError 10013` среды исполнения; полный повтор с разрешённым loopback успешен.
