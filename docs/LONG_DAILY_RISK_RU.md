# Два независимых дневных лимита LONG / ИИС

Изменение согласовано 23.11.2026. Это **не допуск и не включение PROD**.

| Контроль | База | Доля | Пример |
|---|---|---|---|
| Собственный результат LONG | выделенный капитал `capital_limit_rub` | `max_strategy_daily_loss_weight` = 0.015 | 40 000 × 1.5% = 600 ₽ |
| Совокупный результат ИИС, включая ручные позиции | фактический капитал в начале дня МСК | `max_account_daily_loss_weight` = 0.015 | 160 000 × 1.5% = 2 400 ₽ |

Вход блокируется при достижении **любого** лимита (включая точное равенство).
Плановый риск покупки со стопом и резервом издержек также ограничен бюджетом LONG,
а не увеличенным бюджетом счёта. Стоп не гарантирует предельный убыток: гэп,
проскальзывание или отсутствие ликвидности могут привести к большему результату со знаком минус.
Лимиты капитала, стоимости лота, резерв средств/ГО и GetMaxLots остаются прежними.

## Доказательства и ограничения первого входа

Результат ИИС: `текущий NAV − начальный NAV − внешние денежные потоки`.
Используется totalAmountPortfolio в RUB, а не доступные для покупки деньги после ГО.
Брокерский `dailyYield` не используется вместо этой формулы и не вычитается из
текущего капитала для восстановления якобы начального снимка.

Начальный снимок фиксирует read-only service `moex-tinvest-daily-risk` в 00:00:05
МСК. Допустимо только первое минутное окно дня, сбор не дольше 20 секунд.
Поздний запуск, пропущенный день или недоступность API означают UNKNOWN: новый
вход запрещён. Предыдущий день не подставляется; внутридневная база не создаётся.
Файлы root-only для записи, эксклюзивное создание, SHA-256, привязка к счёту/дню;
перезапись запрещена. Таймер без Persistent и без догоняющего запуска.

Перед входом повторно читаются NAV, денежные остатки и полная цепочка операций.
Внешний поток — только однозначные RUB INPUT/OUTPUT. Комиссии, дивиденды, налоги
и вариационная маржа остаются частью результата. Сумма денежных операций должна
совпасть с изменением полного рублёвого остатка. Если пополнение уже в остатке,
но операция запоздала, результат UNKNOWN, а не искусственная прибыль.
Операции читаются повторно до конца снимка NAV: изменение состава/содержимого
операций либо операция во время чтения дают UNKNOWN. У API нет общего атомарного
среза NAV и операций: полностью неотданные брокером взаимокомпенсирующие проводки
невозможно доказать этими ответами. Согласованность двух чтений — не гарантия
полноты брокерского учёта. Это ограничение остаётся в материалах допуска; отчёт
дневного риска сам по себе не разрешает PROD и не заменяет итоговую сверку.

Начальная реализация для **одной первой покупки** требует неизменных количества
бумаг и валютных остатков со снимка начала дня. Ручная сделка, перевод бумаг,
неподдерживаемая операция или несогласованные ответы блокируют новый вход с
причиной. Неизменные ручные позиции, включая KCG7, оцениваются в NAV; продавать
их бот по-прежнему не вправе. Это ограничение достоверности учёта, не новый сигнал.

Нулевой результат LONG подтверждается только пустым зарегистрированным журналом
исполнения с совпадающими счётом и UUID. Проверка повторяется внутри транзакции
резервирования заявки. После любой попытки нельзя снова объявить результат нулём:
второй вход и так запрещён одноразовым разрешением. Для многократных будущих входов
потребуется отдельный учёт фактических исполнений, закрытий и комиссий LONG.
UNKNOWN дневного риска не блокирует разрешённую продажу собственных бумаг,
постановку стопа после покупки и восстановление защиты.

## Установка и проверка (без торговых заявок)

Штатный update.sh устанавливает код и unit-файлы, создаёт каталог базы,
но сам не включает новый таймер. Отдельная активация read-only наблюдения:

```bash
sudo systemctl enable --now moex-tinvest-daily-risk.timer
sudo systemctl list-timers moex-tinvest-daily-risk.timer
sudo journalctl -u moex-tinvest-daily-risk.service -n 30 --no-pager
sudo -u moexbot bash -c 'set -a; source /etc/moex-tinvest-bot/bot.env; set +a;
exec /opt/moex-tinvest-bot/.venv/bin/python -m moex_bot.daily_risk_operator report'
```

`report` показывает обе базы/лимита, P&L, денежные потоки и конкретную причину
UNKNOWN. Не содержит токенов или ID счёта. `EVIDENCE_READY_NOT_A_GRANT` означает
только успешную проверку дневного риска, не сигнал и не разрешение торговли.
В день установки без сохранённой утренней базы UNKNOWN ожидаем до следующего дня.

Для старых конфигов без `max_strategy_daily_loss_weight` оставлена **старая**
консервативная проверка. Новый шаблон явно включает разделённые базы. Миграция
сохранённого `/etc/moex-tinvest-bot/prod-long.json` должна добавить ровно это поле
со значением `"0.015"`, не менять другие настройки. Изменение входит в digest
политики/релиза и инвалидирует прежний допуск; новый допуск автоматически не выдаётся.
Снимки BOD включаются в prod-control sidecar штатного бэкапа, если этот контур
инициализирован. Восстановление старого снимка не позволяет использовать его
в другой день. Не удаляйте текущий снимок для обхода дневного лимита.
