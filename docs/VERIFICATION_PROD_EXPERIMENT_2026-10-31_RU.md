Shell-скрипты не входят в знаменатель Python coverage: для них проверены синтаксис,
регрессионные контракты, Linux-native блокировки и изолированная установка.
В Windows pytest сообщил только предупреждение о недоступном cache; тесты и
выгрузка XML/coverage завершились успешно.

Проверены отказ при неоднозначном ответе без повторной отправки, привязка стопа
к фактически исполненному входу, защита ручных позиций, точный hash парного preview,
expiry, root-review, отмена только новой неисполненной заявки, запись evidence до
сетевого запроса, fsync файлов/каталогов и исключение одновременного обновления.
Восстановление проверено на согласованных копиях двух SQLite-журналов; это не
полное восстановление новой виртуальной машины.

## Что этим НЕ проверено

Брокерские изменения в тестах замоканы. Реальные `PostOrder`, `PostStopOrder` и
`CancelOrder` в рамках подготовки не вызывались. Проверка API только чтением
не доказывает, что исполнение реальной заявки или стопа сработает без расхождений.
100% покрытия не означает отсутствие всех ошибок и не подтверждает прибыльность.

Сборка допустима к установке с отключённым экспериментальным профилем. Первый
реальный вход требует свежего preview, последующего точного подтверждения,
актуального экспериментального review и присутствующего оператора. Автономный
PROD по-прежнему не допущен; старые strategy promotion gates не изменялись.
