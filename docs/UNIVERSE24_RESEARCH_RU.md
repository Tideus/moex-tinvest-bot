## Правила допуска к исследованию

Котировка должна быть реально полученным bid/ask, с временем биржи и получения,
возрастом не более 3 секунд, актуальным статусом торгов и проверенным лотом.
Метаданные инструмента должны быть не старше 7 дней. Времена каждой бумаги
сохраняются отдельно: последовательный сбор 24 инструментов не является одним
одновременным снимком рынка.

Максимальный спред — 10 б.п.; медианный оборот за предыдущие 20 полных сессий —
не менее 50 млн рублей. Данные сегодняшнего и будущих дней не входят в расчёт.
Условная заявка ограничена 10 000 рублями и округляется до целого лота.
Она не должна превышать 10% доступного объёма лучшей цены ни на одной стороне
стакана. Недостаточная глубина записывается как отказ, отдельно сохраняется
возможная доля объёма. Это оценка ёмкости стакана, а не подтверждение исполнения.

Расчётный круговой расход: наблюдаемый полный спред + 5 б.п. комиссии на сторону
+ 5 б.п. проскальзывания на сторону; предел — 30 б.п. Также сохраняется стресс 2×.
Пороги фиксированы как исследовательские ограничения, не подобраны для получения
положительного результата. Прошедшее движение цены не объявляется прогнозом прибыли.

Отсутствующая бумага, неверная котировка и недостаточная история всегда отражаются
в отчёте. Допуск по ликвидности не означает сигнал, прибыльность или разрешение покупки.
Докупки и увеличение торгового риска этим дополнением не включаются.

## Воспроизведение истории

Из корня репозитория, Python 3.12, после `python -m pip install -e '.[dev]'`:

```bash
python scripts/research/universe_history.py fetch \
  --start 2026-09-01 --end 2026-11-11 \
  --data work/universe24-20261111/data \
  --output work/universe24-20261111/download.json
python scripts/research/universe_history.py report \
  --start 2026-09-01 --end 2026-11-11 \
  --data work/universe24-20261111/data \
  --output work/universe24-20261111/history-report.json
```

Используйте новый каталог для новой даты данных. JSON-результаты не перезаписываются.
Загрузчик запрашивает дневные свечи с 2017 года для прогрева индикаторов;
десятиминутные — только за указанный период. CSV, манифесты и отчёт входят в архив.
Для LQDT учитываются обе доски TQTF/TQBR; пересечение дат вызывает ошибку.

Исследования сигналов:

1. LONG: завершённый первый торговый день месяца выше SMA200, вход по открытию
   следующей сессии, оценка по открытию через 20 сессий.
2. Intraday: падение за первый час ниже −0,5%, условный вход 11:10,
   оценка 13:10. Требуются все шесть свечей первого часа и все свечи удержания.

Это **проверка последующего изменения цены сигналов**, а не полный портфельный
бэктест и не точное воспроизведение торговых стратегий бота. Здесь нет стопов,
прибыльных целей, капитальных ограничений, фактических исполнений или шортов.
Исторический стакан не восстанавливается из свечей. Расходы — модельные:
комиссия 5, половина спреда 5 и проскальзывание 5 б.п. на сторону; стресс 2×.
Дивиденды и налоги не включены, исторические лоты не подтверждены. Выбор нынешних
24 бумаг создаёт смещение выживших; период уже изучался, это не независимый holdout.
Разрыв цены от 40% вызывает карантин индикатора; проверка не заменяет полный
реестр корпоративных событий и не исключает события меньшего размера.

Получено 56 034 дневных и 147 281 десятиминутных свечей акций, плюс 290 дневных
свечей LQDT. Ошибок загрузки 24 акций не было. За 01.09–11.11.2026:

| Сигнал и группа | Завершённых наблюдений | Среднее после расходов 1× | При 2× |
|---|---:|---:|---:|
| Intraday, контрольные 3 | 26 | −26,78 б.п. | −56,70 б.п. |
| Intraday, дополнительные 21 | 186 | −29,34 б.п. | −59,25 б.п. |
| Intraday, все 24 | 212 | −29,02 б.п. | −58,93 б.п. |
| LONG, все 24 | 5 | +545,13 б.п. | +513,78 б.п. |

У LONG лишь пять наблюдений по LKOH/TATNP/TATN, причём два последних тикера
относятся к одному эмитенту. Контрольная группа не дала завершённых наблюдений.
LQDT за те же пять интервалов дал в среднем +43,17 б.п. при той же модели расходов.
Это средние изменения стоимости отдельных условных позиций, не доходность счёта.
Малой и зависимой выборки LONG недостаточно для вывода о прибыльности.
Intraday остаётся отрицательным; расширение числа инструментов не решило проблему.

## Подключение отдельного наблюдателя

Команда ниже готова для запуска на сервере с доступом к T-Invest. Её сетевой вызов
в этой сессии не проверен: проверены контракт на тестовых ответах и запреты транспорта.
Лоты стакана API пересчитываются в акции по свежему ответу GetInstrumentBy,
а не по историческому допущению. Брокерские ошибки сохраняются без текста и заголовков.

```bash
python scripts/research/universe_capture.py \
  --data work/universe24-20261111/data \
  --output work/universe24-forward/capture-20261113T101500.json
```

Имя каждого файла должно быть новым и начинаться с `capture-`. План наблюдения:
каждые 5 минут с 10:15 до 18:20 МСК включительно, 98 снимков за подтверждённую
торговую сессию. Допуск старта — 30 секунд. Это дополнительный наблюдатель;
он не заменяет существующий подробный поток котировок и не измеряет исполнение
заявки с секундной точностью. Перед постановкой на расписание на vivek следует
проверить текущие файлы sidecar, доступный read-only источник, календарь и квоты API.
Сервисы бота перезапускать для этого не требуется.

После завершения дня:

```bash
python scripts/research/universe_watch.py session \
  --input work/universe24-forward --date 2026-11-13 \
  --output work/universe24-forward/session-20261113.json
```

Полнота пересчитывается из сохранённых снимков: хеш профиля, время, содержимое
проверок, отсутствующие интервалы и доля валидных котировок. Дубликаты и
несовпадение сохранённого результата с исходным снимком вызывают ошибку.
При отсутствии данных вместо удачной сессии получается нулевая полнота.

Для готовых intraday-планов и уже существующей подробной ленты bid/ask:

```bash
python scripts/research/universe_watch.py markout \
  --input work/archived-intraday-plans --quotes work/top-of-book.jsonl \
  --output work/markout-cohorts.json
```

Формат ленты и расчёт 5/15/30/60 минут остаются такими же, как у
`intraday_markout.py`: `secid`, `at` с часовым поясом, `bid`, `ask`, `session`.
Существующий расчёт учитывает bid/ask и комиссии; неизвестное проскальзывание
реального исполнения не становится измеренным расходом. Без `--quotes` результат
явно помечается как `5m_close_spread_proxy`. Редкие снимки нового наблюдателя
нельзя выдавать за непрерывную подробную ленту. Отказы и неполные горизонты
сохраняются; группы planned/filter_rejected не смешиваются.

## Недельная проверка

`weekly --input receipts.json --output weekly.json` принимает JSON-массив дневных
отчётов `session`. Для операционной проверки нужны 10 полных сессий и не менее
95% валидных котировок; сегодняшний незавершённый и будущие дни не засчитываются.
Это порог готовности данных к рассмотрению, не доказательство доходности.
Результат всегда сохраняет `promotion_to_trading: false`,
`profitability_status: NOT_ESTABLISHED`, `parameter_changes: []`.
Еженедельная ИИ-задача из предыдущего этапа остаётся прежней; новую не создавали.
