# Деньги в PROD OBSERVER

Observer читает ИИС, но не отправляет заявки. Результат проверок не является
допуском к реальному исполнению. Рабочие стратегии, лимиты и расписание не меняются.

## Источники и расчёт

1. Штатный снимок: `GetPortfolio`, `GetPositions`, `GetOrders`, операции.
2. Дополнительно `GetWithdrawLimits`: деньги, обычные блокировки и
   `blockedGuarantee` — ГО, в том числе по защищённым ручным фьючерсам.
3. Консервативная оценка собственных денег:
   `max(0, min(GetPositions.money RUB, GetWithdrawLimits.money RUB − blocked RUB − blockedGuarantee RUB))`.
   Блокировки из двух методов не суммируются повторно. Отрицательный результат
   означает нулевую возможность покупки; исходные значения сохраняются.
   Это консервативная оценка, а не обещание доступности вывода денег с ИИС.
4. Бюджет LONG — минимум этой оценки и существующего `capital_limit_rub`.
   Затем применяется существующий резерв `min_cash_reserve_weight`.
5. Для BUY, прошедшего штатный риск-контроль: `GetMaxLots` с точной лимитной
   ценой и UID. Используются только `buyLimits.buyMaxLots` и `buyMoneyAmount`;
   `buyMarginLimits` никогда не даёт права на покупку.
6. `GetOrderPrice` проверяет сумму с комиссией. Все ранее одобренные в этом
   shadow-плане BUY резервируют полную стоимость. Продажи из shadow-плана
   не пополняют доступные деньги, поскольку ещё не исполнены.

Устаревший (более 300 секунд), будущий, чужой или неполный снимок денег
не используется. Отсчёт начинается до первой операции получения снимка счёта.
Отсутствующий/повреждённый ответ не заменяется нулём. Пустые повторяемые поля
`blocked` / `blockedGuarantee`, штатно опускаемые protobuf JSON, считаются пустыми
массивами. При ошибке GetMaxLots/GetOrderPrice конкретный кандидат получает
`UNAVAILABLE` с названием API; остальные могут быть проверены независимо.
Нулевой лимит брокера — `REJECTED`, а не сбой API. Объём автоматически не уменьшается.

## Отчёт и история

Telegram различает весь ИИС и **бюджет LONG**. Отдельно показаны время среза МСК,
деньги GetPositions, блокировки, ГО, консервативно доступная сумма,
резерв LONG, бюджет покупок, план с комиссией и результат GetMaxLots по кандидатам.
JSON содержит `observer_funding`, проверенные суммы и время каждого запроса.
Для бумаг, отклонённых раньше риск-контролем, GetMaxLots не вызывается.

Утренний отчёт остаётся снимком на момент цикла, а не текущим балансом весь день.
Старые планы не переписываются. Старые снимки без `observer_funding` нельзя
использовать для нового плана: нужен новый штатный read-only снимок.
Sandbox и live-executor этим изменением не переключаются и не получают допуск.

## Проверки

Регрессии: ГО и блокировки, минимум двух источников, ограничение бюджета,
неполные/NaN/устаревшие ответы, чужой счёт, отсутствие собственных лимитов при
наличии маржинальных, точная цена и количество лотов, комиссии, несколько BUY,
отказ без расходования бюджета, отсутствие кредита от виртуальной продажи,
сохранение отказов и отчёт, запрет мутирующих методов.
