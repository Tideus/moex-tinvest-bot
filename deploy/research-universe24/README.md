# Серверное shadow-наблюдение 24 акций

Основа — коммит `a95e28572fa97e4b2acf106992f91c3c5fb50461`. Серверная обвязка
добавлена 13.11.2026 и не меняет параметры торгового бота или профиля исследования.
Рабочий бот обновляется отдельно штатным `scripts/ubuntu/update.sh` до проверенного
потомка `a95e285`, включающего серверную обвязку и исправления совместимости.

## Границы

- Отдельный пакет `/opt/moex-universe24-a95e285-r3`, журнал
  `/var/lib/moex-research-universe24`, пользователь systemd `moexuniverse24`.
- Контрольные SBER/ROSN/CHMF, дополнительные 21 и все 24 показываются отдельно.
- Старый `moex-research-forward.service` и его семь тестовых моделей не меняются.
- Это **наблюдение за доступностью и ликвидностью**, а не генератор сделок и не
  доказательство прибыльности. Исторические L1/I2 остаются диагностическими probes;
  автоматическое изменение стратегий и перевод в торговлю отсутствуют.
- Нет API счетов, заявок, стопов, доступа к брокерским снимкам или live journal.
  Сборщик знает только read-only ключ и три рыночных RPC. Календарь использует
  TradingSchedules и MOEX APIM session. Название env-переменной не доказывает
  брокерские права токена: сам токен должен быть создан «Только чтение».
- Launcher очищает окружение по положительному списку; unit закрывает рабочие
  директории бота и старого исследования. Отчёт работает вообще без сети/секретов.
  Путь к чужому DynamicUser StateDirectory помечен необязательным: systemd уже
  скрывает этот private-каталог в namespace, поэтому обязательный путь вызывает
  226/NAMESPACE. Если путь существует в namespace, запрет всё равно применяется.

## Время и полнота

Календари T-Invest и MOEX TQBR должны совпасть. Праздник, расхождение, отсутствие
календаря или сокращённая сессия не подменяются обычным рабочим днём.
В TradingSchedules передаётся календарная метка `00:00 UTC` нужной даты, а не
московская полночь: последняя попадает на предыдущую дату UTC и вызывает
ошибку T-Invest `30003` / HTTP 400. Подтверждено сравнением реальных запросов.
Ошибки календаря видны в health/journal; повторяется запрос не чаще раза в минуту.
TLS-контекст проверки сертификатов создаётся один раз на пакет котировок и
используется повторно без отключения проверки имени/цепочки. Это устраняет
повторную загрузку CA для каждого RPC при ограничении CPU; предел свежести
статуса и котировки остаётся 3 секунды. Ошибки валидации имеют безопасный этап
(например, `trading_status_freshness`), без заголовков запросов и секретов.
История оборота обновляется с 09:35 МСК: последние 90 календарных дней, только
завершённые дни Москвы. Проверки используют предыдущие 20 сессий.

98 снимков за полную сессию: 10:15–18:20 МСК каждые 5 минут. Допуск старта 30 секунд.
Слот резервируется до запроса; перезапуск не создаёт дубль и не догоняет пропущенное
решение. Время каждого тикера отдельно; пакет из 24 бумаг не является одновременным.
Технические пробы сохраняются в `commissioning/`, не в `captures/`.
История и входные сведения отделены по дате, raw-ответы и хеши сохраняются.
Ответы календаря сохраняются и при несовпадении источников (`calendar-attempts/`),
а в доверенный дневной кеш попадают только после проверки. Снимки содержат SHA
манифеста пакета. Технические r1/r2-пробы и их ошибки не превращаются в наблюдения r3.

Дневной отчёт — 23:57 МСК, одновременно пересчитывается rolling-сводка готовых дней.
Полные дни должны содержать 98 снимков и >=95% валидных котировок; 10 таких дней
означают готовность данных к рассмотрению, а не допуск к торговле. Недельная
сводка не включает текущую календарную дату до следующего дня.

## Установка

Сначала тесты; затем из проверенного дерева:

```bash
sudo bash deploy/research-universe24/install.sh
systemctl status moex-research-universe24.service
systemctl list-timers moex-research-universe24-report.timer
```

Установщик не трогает торговые unit-файлы и не перезаписывает существующий пакет.
Для стенда: `bash deploy/research-universe24/install.sh --staging /absolute/empty/path`.
Состав установленного пакета проверяется по `BUNDLE_MANIFEST.sha256` перед запуском.
Список 24 инструментов копируется из версии `config/universe.json` этого релиза,
а не из меняющейся серверной конфигурации торгового контура.

## Проверка и отчёты

```bash
sudo journalctl -u moex-research-universe24.service -n 40 --no-pager
sudo cat /var/lib/moex-research-universe24/health.json
sudo systemctl start moex-research-universe24-report.service
sudo cat /var/lib/moex-research-universe24/reports/weekly-latest.json
```

Дневные JSON/Markdown: `reports/YYYY-MM-DD/report-TIMESTAMP.{json,md}`.
`latest.json` — только производное представление; исходные `capture-*` неизменяемы.
Отчёт до 18:25 МСК не объявляет сегодняшний день полным. После простоя отсутствие
наблюдений отражается пропусками, не нулевой доходностью. Повторяющиеся наблюдения
нельзя складывать как независимые сделки. Отказы по спреду/глубине — не отказ стратегии.

Для остановки только этого эксперимента:

```bash
sudo systemctl disable --now moex-research-universe24.service moex-research-universe24-report.timer
```

Telegram и Kuma этой установкой не перенастраиваются. Диагностика источника/этапа
идёт в отдельный journal и `health.json`; ошибки не маскируются ценой ноль.
