# Веб-журнал трейдера

Приватный интерфейс `https://breakwood.ru/journal/`, отдельный пароль, только чтение.
Это отдельная аналитическая база, а не миграция/замена журнала исполнения.
Установка не изменяет стратегии, лимиты, счета, заявки и торговые таймеры.

## Версия 3: SQLite-витрина и read-only API

Браузер больше не скачивает всю историю `data.json`. При открытии он получает
каталог счетов, сводку выбранного периода и 50 закрытий. Операции/сигналы — по 100
строк и только при раскрытии секции; график — по кнопке. CSV явно запрашивает все
отфильтрованные закрытия (до 20 000; при превышении запрос отклоняется, не обрезается).
Печать содержит текущую страницу сделок, а не скрытые страницы.

`readmodel/readmodel.sqlite3` находится вне web-root и содержит таблицы `streams`,
`summaries` (отдельная строка для дня/месяца), `rows` и `metadata`. Индексы
`(stream,kind,day,seq)` и `(stream,kind,month,seq)` обслуживают курсорные страницы.
Это отдельная воспроизводимая витрина: исходные события и журнал исполнения не
мигрируются. FIFO/Decimal, неизвестные комиссии, предупреждения, текущие позиции,
покрытие и Modified Dietz рассчитывает прежний `build_report` по полной истории.
Суммировать месячную доходность из дневных процентов запрещено.

Новая БД целиком собирается во временный файл, проверяется и атомарно публикуется.
Веб-процесс открывает её только `mode=ro&immutable=1`: каждый опубликованный inode
после публикации больше не изменяется. Сбой построения оставляет предыдущую БД.
Отчёт `data.json` сохраняется для сверки/отката, но не используется новой страницей.
Если срез обновился между страницами, API возвращает 409 с требованием обновить
журнал: страницы разных срезов не смешиваются. Запоздавшие ответы интерфейс игнорирует.

API доступен только за прежним HTTPS/Basic Auth в `/journal/api/`:

| GET | Содержание |
| --- | --- |
| `catalog` | Счета/стратегии, доступные даты, `generation`, время и ошибки импорта |
| `summary` | День/месяц, календарь текущего месяца, позиции, качество, сравнение стратегий |
| `trades` | Закрытия; фильтры `symbol`, `direction=LONG/SHORT`, `outcome`, `cost=gross/net` |
| `signals`, `operations`, `orders`, `equity` | Страницы соответствующих записей |
| `health` | Готовность витрины, возраст; 503 при старше 20 минут/ошибках импорта |

Для сводки/строк обязательны `stream`, `period=YYYY-MM[-DD]`, `generation` из каталога.
Для строк: `limit=1..100` (50 по умолчанию), непрозрачный `cursor` из `next_cursor`.
Курсор привязан к срезу, счёту, разделу, периоду и фильтрам. Все значения SQL связаны
параметрами; произвольного SQL/пути БД нет. POST/PUT/DELETE не поддерживаются.

Gunicorn закреплён с SHA256 в `requirements-api.txt` и установлен в отдельную venv.
Сервис `moex-trader-journal-api` слушает только Unix socket, не TCP. Отдельный
пользователь `moexjournal`, файловая система read-only, брокерские конфиги/история
недоступны, сетевые семейства ограничены AF_UNIX. `bot.env` API не получает.
Коллектор по-прежнему отдельный сервис со своим прежним расписанием.
Python-среда API принадлежит `root:www-data`: группа имеет чтение/исполнение,
но не запись. Linux smoke проверяет запуск Gunicorn непривилегированным пользователем
после установки с `umask 027`; отдельный управляющий сокет Gunicorn отключён.

Первичная витрина из уже готового отчёта, без broker API:

```bash
sudo -u moexbot env PYTHONPATH=/opt/moex-trader-journal/src /usr/bin/python3 \
  -m moex_bot.journal_readmodel \
  --source-report /var/lib/moex-trader-journal/public/data.json \
  --output /var/lib/moex-trader-journal/readmodel/readmodel.sqlite3
sudo systemctl enable --now moex-trader-journal-api.service
sudo nginx -t && sudo systemctl reload nginx
```

Эта команда одновременно проверяет точное совпадение всех полей сводок и всех
страниц со старым отчётом. `--compare-only` выполняет только сверку. На время
приёмки остановите только таймер журнала и дождитесь текущего импортера, чтобы
источник не сменился посреди сравнения; после приёмки возобновите тот же таймер.
Регулярный импортер дальше автоматически публикует обе формы отчёта.

## Использование

Выберите стратегию/счёт, день или месяц. По умолчанию показываем результат **без комиссий**.
Верхние карточки показывают LONG и intraday рядом за один выбранный период,
но не суммируют разные счета. Нажмите карточку, чтобы открыть её подробности.
Доступны закрытия в рублях и процентах, календарь, капитал по снимкам, открытые позиции,
брокерские операции и сигналы с причинами отказа. CSV выгружает закрытия выбранного периода.
Сигналы показываются страницами по 100, сначала новые. Кнопка обновления читает
последнюю серверную выгрузку, не запускает торговлю или новый запрос к брокеру.

### Обновление интерфейса 2

Исправление 2.1: JSON/JS/CSS сжимаются nginx только внутри защищённого `/journal/`.
Ожидание заголовков **и полного тела ответа** ограничено 25 секундами. При обрыве,
ошибке входа или повреждённом JSON выводится ошибка; кнопка «Обновить» снова доступна.
Автоматических бесконечных повторов нет. Старый отчёт при неудаче помечается как
предыдущий; запоздавший ответ не может перезаписать результат новой попытки.
Форматировщики дат переиспользуются: вся история не создаёт тысячи объектов ICU.
Это исправления отображения/доставки, не изменение результатов или торговой логики.

- Режим «Месяц»: таблица по дням с покрытием операций и отдельная сводка по бумагам.
  Учитываются только дни имеющейся истории; весь месяц автоматически полным не считается.
- Режим расходов применяется одновременно к рублям и проценту закрытия, доле прибыльных
  закрытий и profit factor. Доходность счёта остаётся net при любом выборе режима.
- Profit factor = сумма положительных результатов / модуль суммы отрицательных.
  При отсутствии убытков отображается «Нет убытков», а не бесконечная эффективность;
  при отсутствии закрытий или неизвестных данных — «—». Части FIFO не независимые сделки.
- Фильтры бумаги, направления и результата влияют только на таблицу закрытий и её CSV;
  сводка, календарь и статистика периода остаются полными. CSV содержит обе версии
  результата и процента, UTF-8 и защиту от интерпретации текста как Excel-формулы.
- «Печать / PDF» открывает штатную печать браузера для выбранной стратегии/периода.
  Сохранение PDF пользователь выполняет в диалоге браузера; отправки на внешний сервис нет.
- График капитала учитывает реальное расстояние во времени между снимками, а не номера
  точек; доходность счёта показывается до четырёх знаков после запятой.
- Сигналы переведены на понятные названия и причины. Неизвестные коды сохраняются,
  а не заменяются предположением. Операции и сигналы свёрнуты в отдельные секции.
- Нулевые и неизвестные комиссии отмечены отдельно. Текущие открытые позиции явно
  отделены от выбранного исторического периода. Новых торговых разрешений нет.

- Процент закрытия = выбранный gross/net P&L / стоимость входа закрываемой части.
  Это не процент счёта; проценты отдельных закрытий не складываются.
- Для шорта знак учитывается; при развороте закрытие и новый вход разделяются.
- Частичные закрытия сопоставляются FIFO. Несколько строк не обязательно несколько заявок.
- Открытая переоценка = текущая подписанная стоимость минус оставшаяся FIFO-база.
- Доходность счёта — net Modified Dietz с учётом подтверждённых внешних потоков.
  Показывается только при наличии покрытия операций брокерской выгрузкой.
- День/месяц ограничен фактически имеющимися снимками: начало/конец окна подписаны.
  Неполный ноябрь не является результатом полного месяца. График капитала не очищен
  от пополнений и не является графиком доходности или точной внутридневной просадки.
- Отсутствующая комиссия не заменяется нулём; net в этом случае не рассчитывается.
  Если старый исходный адаптер уже записал 0, журнал сохраняет это исходное значение.
  Безкомиссионные результаты sandbox нельзя переносить на реальный счёт.
- Неизвестная база входа, неподдерживаемый инструмент или расхождение количества
  помечаются предупреждением, результат не выдумывается. Контроль количества
  сам по себе не доказывает полноту всех закрытых в прошлом кругов.
- Сигнал, план и принятая заявка не равны исполненной сделке.

## Границы первой версии

Подключены LONG sandbox и intraday sandbox, каждый отдельным потоком/счётом.
ИИС/PROD, ручные позиции, идеи и деривативы **не подключены**. Это не скрытый
нулевой результат этих счетов. Их адаптеры требуют отдельной сверки и разработки.
Источник сделок — операции брокера с агрегированным VWAP; если исходные отдельные
биржевые исполнения не сохранены, журнал не имитирует такую детализацию.
Оценки результатов, новости и прогнозы автоматически не меняют стратегию.

## Формат и безопасность

`trader-journal-v1`: SQLite append-only revisions `(stream, kind, identity, known_at)`.
Время события и получения раздельны. Повторный импорт идемпотентен; конфликт одной
ревизии отклоняется. Поздняя корректировка комиссии сохраняется новой ревизией.
В закрытой базе остаются SHA источников/входов анализа. В браузер не передаются
токены, полные ID счетов, ID брокерских операций и приватные конфиги.

Коллектор разрешает только четыре GetSandbox-метода, PROD и записи блокируются.
Если во время чтения снимка возникла новая операция, публикация откладывается
до следующего цикла. При сетевой ошибке остаётся предыдущая выгрузка, на странице
есть её время и предупреждение после 20 минут. Ошибка импорта видна отдельно.

Nginx читает только `public/`; база/receipts находятся вне web-root. Нет внешних
CDN, аналитики, JavaScript-зависимостей или торговых HTTP-endpoint. CSP запрещает
встраивание страницы. Basic Auth передаётся только через HTTPS. Для выхода из
Basic Auth закройте приватное окно браузера; это не сессионная форма входа.

## Установка и управление Ubuntu 24.04

Из проверенной чистой копии проекта:

```bash
sudo bash deploy/trader-journal/install.sh
# Добавить include /etc/nginx/snippets/moex-trader-journal.conf;
# только в существующий HTTPS server для breakwood.ru, сохранив резервную копию.
sudo nginx -t
sudo systemctl enable --now moex-trader-journal-api.service
sudo systemctl reload nginx
sudo systemctl start moex-trader-journal.service
sudo systemctl enable --now moex-trader-journal.timer
```

Пароль создаётся только при первой установке. Посмотреть лично на сервере:

```bash
sudo cat /etc/moex-trader-journal/access.txt
```

Не помещайте этот файл, базу или выгрузки в Git. Обновление отдельного журнала:
остановить только `moex-trader-journal.timer`, дождаться завершения его service,
создать приватную резервную копию `/opt/moex-trader-journal`, `/etc/moex-trader-journal`,
`/var/lib/moex-trader-journal` и nginx snippet, повторить установку из проверенной
копии, `nginx -t`, перезапустить только сервис/таймер журнала. Конфиг и пароль не
перезаписываются. Core `update.sh` намеренно не меняется этим релизом.

```bash
systemctl status moex-trader-journal.timer
systemctl show moex-trader-journal.service -p Result -p ExecMainStatus
journalctl -u moex-trader-journal.service -n 30 --no-pager
# Остановить сбор; это не останавливает торгового бота:
sudo systemctl disable --now moex-trader-journal.timer
```

Для аварийного закрытия веб-доступа удалите только include журнала из HTTPS server,
проверьте `nginx -t`, reload. Данные сохраняются. Перед восстановлением SQLite
сервис импорта должен завершиться; весь read model можно пересобрать из исходных
артефактов и receipts, не откатывая торговой журнал.

## Конфигурация `/etc/moex-trader-journal/config.json`

| Параметр | Значение/влияние |
| --- | --- |
| artifact_root | Корень существующих артефактов, только чтение |
| universe | Проверенные UID, класс актива, размер лота для перевода в штуки |
| collector_dir | Приватные снимки сверки, не web-root |
| database | Отдельная SQLite, не execution journal |
| output | Каталог обезличенного data.json для nginx |
| history_from | Начало полной запроса истории операций; не старт оценки капитала |
| profiles[].id | Имя стратегии/потока; разные счета не объединяются |
| profiles[].environment | В этой версии только sandbox |
| profiles[].account_env | Имя переменной ID счёта, не само значение |
| profiles[].portfolio_globs | Разрешённые шаблоны исходных снимков |

Обновление — каждые 5 минут после окончания предыдущего цикла. systemd не запускает
один oneshot параллельно с собой. Время всех экранов — Europe/Moscow.

## Выбор реализации и проверка

Проверен отдельный прототип round-trip matcher [LuxAlgo trade-journal](https://github.com/LuxAlgo/trade-journal)
(`834e7b68f553d1aba0d7777875cdc4622f5a7eb5`): long, short, частичное закрытие,
разворот, несколько входов — пять синтетических сценариев. Полный форк не принят:
нашему журналу нужны Decimal, неизвестная начальная база, доказательство покрытия
и раздельная provenance. Чужой код в рабочую реализацию не включён.

Регрессионные тесты: FIFO, комиссии, часовые пояса, внешние потоки, недостающая
история, сверка остатков, разные счета, повторный импорт/конфликты, запрет PROD и
изменяющих API, приватность выдачи. Проверять Ruff, strict mypy, полный pytest и
Linux deployment smoke. `linux-test.sh` — процедура одноразовой изолированной
проверки на текущем vivek, пути тестовых зависимостей не переносимы на новую VM.
`probe.py` — необязательная приёмка в отдельном приватном каталоге, только чтение
sandbox. Производственная установка не включает тестовые данные.

Тесты чистой браузерной модели (Node.js, без установки пакетов):

```bash
node --test deploy/trader-journal/test-model.cjs
node --test deploy/trader-journal/test-loading.cjs
node --test deploy/trader-journal/test-api-ui.cjs
# Linux, локальный одноразовый nginx на loopback, только синтетическая история:
python3 deploy/trader-journal/test-nginx.py
```

Проверяются gross/net, неизвестные комиссии, границы суток МСК, фильтры, переход
месяца/года, временная шкала графика и защита CSV. Браузерная приёмка выполняется
на явно помеченной синтетической истории; перенос приватной серверной истории
на рабочий компьютер не является необходимым шагом установки.

Для Linux `test-nginx.py` задайте `JOURNAL_TEST_GUNICORN` абсолютным путём к
тестовому gunicorn: проверяется настоящий WSGI + временный nginx, только loopback,
синтетические записи/пароль, авторизация, gzip, лимиты страниц и конфликт версий.
Python-тесты отдельно проверяют parity, границы месяца, отсутствие дубликатов,
неизвестные комиссии, read-only доступ, индексы и атомарную публикацию.
